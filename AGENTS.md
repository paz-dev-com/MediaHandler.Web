# AGENTS.md — MediaHandler Web

Personal media management frontend (Freebox NAS + TMDB + Auth0). Angular 21 · TypeScript 5.9 · PrimeNG 21 · Transloco · Vitest.

---

## Architecture

Feature-based standalone-component architecture — no NgModules:

```
core/      ← singleton infrastructure (api, auth, i18n, layout, services)
features/  ← one folder per feature, lazy-loaded via its own .routes.ts
shared/    ← reusable models, components, pipes, directives, animations, constants
```

Dependency direction: `features` → `core` / `shared`. Never import a feature from another feature; never import `features` from `core` or `shared`.

| Area     | Path                       | Key contents                                                                              |
| -------- | -------------------------- | ----------------------------------------------------------------------------------------- |
| Core     | `src/app/core/`            | `ApiService`, auth (guards, interceptors, Auth0), i18n loader, layout, app-level services |
| Features | `src/app/features/<name>/` | Page + child components, feature service (signal state), `<name>.routes.ts`               |
| Shared   | `src/app/shared/`          | TypeScript models, reusable components/pipes/directives, animation config                 |

Path aliases (use them, never deep relative imports): `@core/*`, `@shared/*`, `@features/*`, `@env/*`.

## Component Conventions

- Standalone components only — explicit `imports: [...]` array, no NgModules.
- `ChangeDetectionStrategy.OnPush` on every component.
- Signal APIs only: `input.required<T>()` / `input<T>()`, `output<T>()`, `signal`, `computed`. No `@Input()`/`@Output()` decorators.
- `inject()` function instead of constructor parameters.
- Separate files per concern: `<name>.component.ts` / `.html` / `.scss` (no inline templates/styles).
- One component per file; page components named `<name>-page.component.ts`.
- User-facing text goes through Transloco (`TranslocoModule` in imports) — never hardcode strings in templates.
- PrimeNG modules imported per-component (`ButtonModule`, `TagModule`, …); layout spacing via PrimeFlex classes.

```typescript
@Component({
  selector: 'app-media-card',
  templateUrl: './media-card.component.html',
  styleUrl: './media-card.component.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
  imports: [RouterLink, TranslocoModule, ButtonModule],
})
export class MediaCardComponent {
  readonly media = input.required<Media>();
  readonly watchedToggle = output<{ mediaId: string; isWatched: boolean }>();
}
```

## HTTP & State Conventions

- All HTTP goes through `ApiService` (`core/api/api.service.ts`) — never inject `HttpClient` into feature code. Responses are always `Observable<ApiResponse<T>>`; paginated endpoints add `meta`.
- Feature state lives in an `@Injectable({ providedIn: 'root' })` feature service exposing readonly `signal`s and `computed`s; components never hold server state.
- Mutations update the local signals after a successful response (no full reload unless the design says so).
- Errors: the global `errorInterceptor` already shows a translated toast for API errors — feature code only sets its own `error` signal when the UI needs an inline state. Add a `SILENT_ERRORS` entry in the interceptor for expected non-error statuses (e.g. 404 on `/auth/me`).
- API paths are relative to `environment.apiBaseUrl` without the leading slash: `api.get<Media[]>('media', { page, pageSize })`.

## Routing & Auth

- Top-level routes in `app.routes.ts`; each feature lazy-loads its own `<feature>.routes.ts` via `loadChildren`.
- Authenticated features: `canActivate: [authGuard]`; admin features: `canActivate: [authGuard, adminGuard]`.
- Route `data: { animation: '<Name>Page' }` for page transitions.
- Auth0 via `@auth0/auth0-angular`; `authInterceptor` attaches tokens — feature code never touches tokens.

## i18n

- Bilingual en/fr. Every user-facing string must have a key in **both** `src/assets/i18n/en.json` and `src/assets/i18n/fr.json`.
- A change that adds a key to only one file is incomplete.

## Unit Test Pattern (Vitest)

Tests run with Vitest via `@angular/build:unit-test`. Globals (`describe`, `it`, `expect`, `vi`) are available without imports.

**Service tests** — `HttpTestingController`, assert method + URL + params, `httpMock.verify()` in `afterEach`:

```typescript
TestBed.configureTestingModule({
  providers: [MyService, provideHttpClient(), provideHttpClientTesting()],
});
const req = httpMock.expectOne(`${base}/admin/media/unlinked-files`);
expect(req.request.method).toBe('GET');
req.flush({ data: [] });
```

**Component tests** — TestBed with the component's real imports, plus:

```typescript
await TestBed.configureTestingModule({
  imports: [
    MyComponent,
    TranslocoTestingModule.forRoot({
      langs: { en: {}, fr: {} },
      translocoConfig: { availableLangs: ['en', 'fr'], defaultLang: 'en' },
    }),
  ],
  providers: [provideRouter([]), provideNoopAnimations()],
  schemas: [NO_ERRORS_SCHEMA],
}).compileComponents();

fixture.componentRef.setInput('media', makeMedia()); // set signal inputs via componentRef
```

- Browser APIs (`IntersectionObserver`, …): `vi.stubGlobal` in `beforeEach`, `vi.unstubAllGlobals()` in `afterEach`.
- Use factory fixtures (`makeMedia()`) for model objects.
- Assert real behavior: signal values, emitted outputs, rendered DOM — not just `toBeTruthy()`.

## Code Style

- Prettier enforced: `printWidth: 100`, single quotes, Angular parser for HTML. Run `npm run format` before finishing.
- Strict TypeScript (`strict`, `strictTemplates`, `noImplicitOverride`, …) — no `any`, honor nullability.
- SCSS per component; BEM-style class names (e.g. `.media-card__poster-placeholder`).
- The dark theme is the custom `CinematicPreset` in `app.config.ts` — use PrimeNG semantic tokens/CSS variables, not hardcoded colors.
- No secrets in source — configuration comes from generated environment files.
